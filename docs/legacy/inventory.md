# Legacy pipeline inventory

This inventory documents the Spark reference system and the parallel Rust paths on `demo-prepared`. The Scala jobs remain runnable and provide the parity reference. The four Rust implementations and their fixture tests are present on this branch. [Spark job sources](../../spark_jobs/analytics/src/main/scala/telemetry/analytics/) · [Rust analytics sources](../../rust_pipeline/src/analytics) · [Dependency map](dependencies.md) · [Migration slices](migration-slices.md)

Table names below are Delta paths under `./delta_output` locally or `/opt/delta_output` in Docker. Spark selects the local paths with `--local`. Rust selects its container paths when `/opt/config` or `/opt/spark-jobs` exists. Kubernetes configures `/opt` and an in-cluster Kafka bootstrap address. Types use Spark/Delta names (`bigint` = signed 64-bit, `int` = signed 32-bit). ## Streaming jobs

| Job | Input, processing and output |
|---|---|
| PySpark telemetry, `streaming_job.py` | Reads Kafka `vehicle_telemetry`, starting at earliest on a fresh checkpoint, with `failOnDataLoss=false`. Parses JSON, retains Kafka metadata, applies T1–T7 enrichment, and drops the Kafka key after enrichment. Appends to `vehicle_telemetry` with schema merge and partitions `event_year`, `event_month`, `event_type`. Uses a Spark Structured Streaming checkpoint. [streaming_job.py · source and sink](../../spark_jobs/streaming_job.py#L147-L247) · [streaming_job.py · checkpoint](../../spark_jobs/streaming_job.py#L302-L320) |
| Rust telemetry, `rust-pipeline stream` | Consumes `vehicle_telemetry` with its own consumer group and manual partition assignment. Deserializes JSON, skips parse failures, applies the Rust enrichment transforms, builds Arrow batches and appends to `vehicle_telemetry_rust` with the same three partition columns. Stores next offsets in SQLite after the Delta write. Delta and SQLite commits are separate. [rust_pipeline/src/consumer.rs](../../rust_pipeline/src/consumer.rs) · [rust_pipeline/src/writer.rs](../../rust_pipeline/src/writer.rs) · [rust_pipeline/src/checkpoint.rs](../../rust_pipeline/src/checkpoint.rs) · [rust_pipeline/src/transforms/mod.rs](../../rust_pipeline/src/transforms/mod.rs) |
| PySpark vehicle state, `vehicle_state_job.py` | Reads Kafka `vehicle_state_updates` from earliest on a fresh checkpoint, with `failOnDataLoss=false`, then filters out null VINs. Per micro-batch and VIN, selects the greatest sequence, sums `event_count` and takes the minimum `first_seen_at`. Creates `vehicle_state` partitioned by `model` and then MERGEs on VIN. Inserts unseen VINs. A newer sequence updates latest fields, adds the batch count and keeps the earliest first-seen value. If a batch mixes previously applied and new snapshots for the same VIN, its whole count is added when the newer sequence wins. [spark_jobs/vehicle_state_job.py](../../spark_jobs/vehicle_state_job.py) |
| Rust vehicle state, `rust-pipeline state` | Reads Kafka `vehicle_state_updates` with its own consumer group, manual partition assignment and SQLite offsets. Collapses valid snapshots by VIN and uses a sequence-guarded MERGE into `vehicle_state_rust`, partitioned by `model`. Offsets advance after the Delta write. Rust uses a direct count addition and a comparison/CASE expression for first-seen time. With malformed or incomplete snapshots these can differ from Spark's target-count coalesce and null-skipping `least`. [rust_pipeline/src/vehicle_state.rs](../../rust_pipeline/src/vehicle_state.rs) · [rust_pipeline/src/checkpoint.rs](../../rust_pipeline/src/checkpoint.rs) · [Spark state MERGE](../../spark_jobs/vehicle_state_job.py#L120-L143) |

**Deployment.** Both PySpark streams run continuously via `spark-submit` in the Compose Spark 3.5.1 standalone cluster, started manually or by Pipeline Jobs in the dashboard. Both offer `--local` for local Spark. Both Rust streams run through the local binary, through the Compose `rust-pipeline` container with `docker exec`, or as Kubernetes Deployments using `kubectl apply -k deploy/k8s`. In Kubernetes each gets one replica, the `Recreate` strategy and a separate PVC for output, offsets and logs. The manifests wire the streams to an existing Kafka bootstrap service. ### Enriched telemetry schema

The Spark output retains the raw-payload columns listed above except VIN and precise coordinates. `odometer_km` defaults to 0. The added columns are listed here. The Rust output has the same names and logical types except `kafka_timestamp`, a Spark `timestamp` and a Rust `bigint` in epoch milliseconds. Stream validation ignores that column. [streaming_job.py · projection and sink](../../spark_jobs/streaming_job.py#L197-L245) · [spark_jobs/transforms.py](../../spark_jobs/transforms.py) · [schema.rs · telemetry output](../../rust_pipeline/src/schema.rs#L151-L218) · [validate.rs · timestamp exception](../../rust_pipeline/src/validate.rs#L34-L42) · [Spark telemetry fixture](../../rust_pipeline/tests/fixtures/input/telemetry)

| Source | Added columns and types |
|---|---|
| Kafka metadata | `topic` string, `kafka_partition` int, `kafka_offset` bigint, `kafka_timestamp` timestamp (Spark) or bigint (Rust) |
| T1 defaults | `model_safe`, `software_version_safe`, `power_state_safe` string |
| T2 UTC time dimensions | `event_date` date, `event_year`, `event_month`, `event_day`, `event_hour`, `event_dayofweek`, `event_quarter` int, `is_weekend` boolean, `date_str` string |
| T3 battery features | `soc_bucket` string, `energy_pct`, `cell_temp_spread`, `degradation_pct`, `km_per_percent` double |
| T4 health flags | `health_tier` string, `thermal_alert`, `is_fault`, `needs_service` boolean, `severity_level` int |
| T5 coarsened location | `lat_coarse`, `lon_coarse` double (rounded to two decimal places) |
| T6 VIN pseudonymization | `vin_hash`, `vin_wmi` string (SHA-256 hex and manufacturer prefix) |
| T7 event features | `row_id` string, `sw_major`, `sw_minor` int |

## Batch analytics jobs

**Spark deployment.** Each named Scala object runs as a one-shot `spark-submit --class telemetry.analytics.<Class>`, manually or from Pipeline Jobs. One sbt project packages `telemetry-analytics_2.12-1.0.0.jar` (Scala 2.12.18, Spark SQL 3.5.1). The job uses a UTC Spark session, reads the configured Delta input paths and overwrites its full `analytics/<job>` Delta table with `overwriteSchema=true`. CI packages the jar. Compose starts the Spark infrastructure, and the repository defines no analytics scheduler or Kubernetes analytics workload.
